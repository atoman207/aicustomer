# 一畳屋 AI相談窓口（AI顧客相談・電話受付システム／デモ）

熊本県の畳店「一畳屋」（株式会社一畳屋・https://ichijoya.co.jp/ ）向けの、AI による問い合わせ・見積受付システムです。
画面は一畳屋サイトと同じヘッダー・ナビ・フッター・ロゴ・画像・配色・フォント・アニメーションで構成し、サイトの一部として違和感なく使えるようにしています（§9）。
**テキスト相談・音声相談・AI電話受付の3つの機能**を、**一畳屋が指定した Googleスプレッドシート（顧客対応マニュアルの指定 1 シート）の内容だけ**を根拠にした**共通ナレッジ**で動かし、
見積依頼は**お客様の確認を経て**スプレッドシートに一元記録します。資料にない内容は推測せず「お答えできかねます（担当者より折り返し）」と案内します。
あいさつ以外のご質問（料金・営業範囲を含む）は、OpenAI が**スプレッドシートの全文を読んで**答えます（NotebookLM と同じ方式。数量の合計はシステムが料金表から計算。前と同じ質問は学習済みの回答をそのまま返し、AI を使いません。§3.5）。

お客様向けの画面は、**トップページの「AIに相談する」の 1 つだけ**（入口を分けない）。同じ画面で**文字でも、マイクのボタンで声でも**相談でき、途中で切り替えても会話はすべて引き継がれます（§9.1）。電話は**ふつうの電話ボタンに「営業時間外・土日はAIが受付」と添えて**案内します。裏側は 3 つとも同じ AI の仕組みです。

| 機能 | お客様の入口 | 技術 |
| --- | --- | --- |
| ① 文字でAI相談 | トップページの相談の画面（`/chat` も同じ画面） | OpenAI Chat Completions（ストリーミング）。資料の全文＋根拠の引用（`OPENAI_ANSWER_MODEL`） |
| ② 声でAI相談 | 同じ画面のマイクのボタン（以前の `/voice` は `/chat?voice=1` へ） | OpenAI GPT-Live（WebRTC・`gpt-live-1`＝ChatGPT の音声会話と同じ、聞きながら話せるモデル。つながらないときは Realtime API の `gpt-realtime-2.1`）＋ function calling。話した内容・AI の答えも同じ会話に文字で残る。マイクの関所（`voice-gate.ts`）：AI の声が流れている間は相づち・物音で AI を止めず、はっきり話し続けたら AI を止めて**話し始めから**送る（訂正「いや、8畳でした」も頭から届く） |
| ③ AI電話受付 | 電話ボタン（`tel:0120158108`）→ Twilio Webhook | Twilio `<Gather input="speech">` ＋ 構造化出力エージェント。スタッフ用のテスト画面 `/phone`（ブラウザ上の通話シミュレーター） |
| LINE 見積受付 | `/api/line/webhook` | LINE Messaging API（③と同じ受付エージェント） |
| 管理画面 | `/admin` | 受付一覧・会話履歴・AI／人間切替・営業時間・ナレッジ・接続状況 |

**OpenAI API キーが未設定でも全画面が動作します**（デモモード：ナレッジのキーワード検索によるテンプレート応答、ブラウザ音声認識・合成）。
`.env` に `OPENAI_API_KEY` を入れて再起動すると、同じ画面がそのまま本番の AI 応答に切り替わります。

## 1. クイックスタート

```bash
npm install
cp .env.example .env        # Windows: copy .env.example .env
# .env に OPENAI_API_KEY と ADMIN_PASSWORD を設定（OPENAI_API_KEY が未設定でもデモモードで動作）
npm run dev                  # http://localhost:3000
```

本番ビルド:

```bash
npm run build
npm start
```

疎通テスト（サーバー起動中に別ターミナルで）:

```bash
npm run smoke
```

## 1.5 Vercel へのデプロイ

GitHub リポジトリを Vercel にインポートするだけでビルド・デプロイできます（追加設定なしで `next build` が通ります）。AI の回答情報源は指定の Googleスプレッドシート（サービスアカウントで読み取り）だけです。シートを読めないときに使う保存版（`database/manual.json`）はビルドに同梱されます（ホームページの内容 `database/website.json` も同梱していますが、既定では回答に使いません）。

**設定する環境変数**（Settings › Environment Variables。変更後は Redeploy で反映。`.env.example` と同じ内容です）。

| 設定 | 目的 |
| --- | --- |
| `OPENAI_API_KEY` | AI 応答・音声・要約・ファイルの解析（未設定時はデモモード） |
| `OPENAI_CHAT_MODEL`・`OPENAI_ANSWER_MODEL` など 7 つ | 使用するモデル（`.env.example` の値のままで可。未設定でも同じ既定値） |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `GOOGLE_PRIVATE_KEY` | Googleスプレッドシートを読み書きするサービスアカウント（鍵の JSON の `client_email`・`private_key`。鍵のファイルはリポジトリに置かない） |
| `KNOWLEDGE_SHEET_ID` / `KNOWLEDGE_SHEET_GID` | 回答に使うスプレッドシートの ID と、タブの gid（URL の `#gid=` の数字）。受付も同じスプレッドシートの「受付一覧」タブに記録（なければ自動で作成） |
| `ADMIN_PASSWORD` | **公開 URL では必須。** 管理画面（受付一覧＝お客様情報、AI／人間切替）を保護（ログインは 1 分に 8 回まで） |

本番運用（VPS・独自ドメインへの移行時など）で必要に応じて追加するもの：

| 設定 | 目的 |
| --- | --- |
| `EMBED_ALLOWED_ORIGINS` | 今のホームページの「AIに相談」の窓（§1.6）として開いてよいサイト（空白区切り。既定 `https://ichijoya.co.jp https://www.ichijoya.co.jp`）。ほかのサイトの中では開けません。**ビルド時に読むので、変えたら Redeploy** |
| `PUBLIC_BASE_URL` | 独自ドメインの公開 URL（例：`https://ai.example.jp`）。Twilio/LINE の署名検証と OGP に使用（Vercel では自動判定） |
| Storage › **Upstash Redis** | 会話履歴・設定・エラー履歴の永続化（Vercel 用）。追加すると `UPSTASH_REDIS_REST_URL/TOKEN` が自動設定されます |
| `TWILIO_*` / `STAFF_FORWARD_NUMBER` | 0120 番号の AI 電話受付（§5） |

**サーバーレスでの保存について**：Vercel ではファイル書き込みが一時的（インスタンスごとの `/tmp`）です。**受付はスプレッドシートの「受付一覧」タブに記録**し、**管理画面の受付一覧と対応状況（未連絡／連絡済）もシートから読み書き**します（再起動・別のサーバーでも同じ一覧。担当者がシートで直した内容・対応状況もそのまま表示）。そのため、スプレッドシートの「共有」にサービスアカウントを**編集者**として追加してください（閲覧者のままだと、回答の読み取りはできても受付を記録できません）。会話履歴・管理画面の設定変更・エラー履歴は、Redis が未設定だと再デプロイやスリープで消えます（VPS ではサーバーの `data/runtime` に保存されます）。

**本番の確認**：設定・Redeploy のあと、管理画面「接続状況」で「Googleスプレッドシート」「受付情報の記録先＝Sheets API」が緑になっていること、テストの見積依頼が「受付一覧」タブに 1 行増えることを確かめてください（確認後、テストの行はシートで削除）。

- ブラウザの電話シミュレーター／音声相談（デモモード）は会話セッションをクライアントと往復させるため、インスタンスが変わっても途切れません
- Twilio の電話受付は通話ごとの Cookie に会話状態を圧縮して持たせるため、Redis なしでも 1 通話内の状態が保たれます
- LINE と管理画面の設定・会話履歴の永続化には Upstash Redis（無料枠あり）の接続を推奨します

管理画面の「接続状況」タブに、現在の保存先（Redis／ファイル／一時保存）が表示されます。

## 1.6 今のホームページ（ichijoya.co.jp）への設置

ホームページの `</body>` の直前に **1 行**貼るだけで、右下に「AIに相談」ボタンが出ます（WordPress ならテーマのフッター、またはフッターにスクリプトを入れるプラグイン）。

```html
<script src="https://aicustomer-flax.vercel.app/embed.js" async></script>
```

- ボタンを押すと、ページの上に相談の窓を開きます（トップページと同じ 1 つの相談の画面。文字でも、マイクのボタンで声でも）。スマホでは画面いっぱい。窓の中ではヘッダー・フッターを出さず、相談の枠だけを表示します
- ホームページのほかのボタンからも開けます：`<a href="#ai-chat">` ／ `<a href="#ai-voice">`、または `window.ichijoyaAi.open("voice")`
- 任意の設定（script タグに書く）：`data-position="left"`（左下に出す）・`data-bottom="80"`（ほかの固定ボタンと重なるとき、下から何 px 上げるか）
- 声の相談は、窓を閉じるとマイクを止めます（会話はその端末に残り、次に開いたときに続きから話せます）。文字と声の会話も引き継ぎます
- **安全のために**：相談のページを窓（iframe）として開けるのは `EMBED_ALLOWED_ORIGINS` のサイトだけ（`Content-Security-Policy: frame-ancestors`）。管理画面はどのサイトの中でも開けません（`frame-ancestors 'none'`・`X-Frame-Options: DENY`）。ボタンと窓は Shadow DOM の中に作るので、ホームページの見た目・動き（CSS・JavaScript）には影響しません
- ホームページのドメインが変わったら（例：`https://www.ichijoya.jp`）、`EMBED_ALLOWED_ORIGINS` に追加して Redeploy

## 3. AI の回答情報源（`database/`）

AI は **指定の Googleスプレッドシートの内容だけ**を根拠に回答し（ホームページは既定では使わない）、記載のない質問は推測せず「担当者より折り返し」を案内します（詳しくは [database/README.md](database/README.md)）。管理画面から情報を追加・アップロードする機能はありません。内容を変えるときはスプレッドシートを直してください。

| 優先 | 情報源 | 内容 |
| --- | --- | --- |
| 1 | **Googleスプレッドシート**（顧客対応マニュアルのタブ。読めないときは同じシートの保存版 `database/manual.json`） | 会社情報・営業時間・営業範囲・よくある問い合わせの文章と、料金表（畳・ヘリ・襖・障子・網戸・ヘリ無し半畳・置き畳・ヘリ有り1畳物・雑工事・カーテンレール） |
| 2 | **ホームページ**（`database/website.json`） | ichijoya.co.jp から学習（会社概要・店舗とスタッフ・畳表や襖紙の特徴など）。`npm run learn:site` または管理画面で再学習。料金がスプレッドシートと違う項目は自動で使わない |

**スタッフからの修正点・要望（「修正点など」のタブ。2026-10-28 一畳屋様のご要望）**：同じスプレッドシートの「修正点など」のタブに、AI の応対への修正点・要望を書くと（1 行に 1 項目。下が新しいもの）、文字・声（GPT-Live とその委任先・Realtime）・電話・LINE の AI の指示に入ります（`src/lib/knowledge.ts` の `loadStaffNotes` → `prompts.ts` の `staffNotesBlock`）。
- 資料と同じく約 1 分で反映（声の相談は、次に声を始めたときから）。管理画面「AIの学習状況・情報源」の ③ に、AI に反映中の内容が出ます
- 会話で守れること（話し方・聞き取り・確認・案内のしかた）は、ほかの指示より優先して守ります。料金などの事実の根拠は ① のシートだけ・日程を約束しない・個人情報の扱いは変えません。仕組みの変更の要望（「〜を学習させて」など）は、AI ではなく開発側で対応します
- 長いとき（4,000 字超）は新しい項目を残します。読めなかったときは前に読んだ内容を使い続けます。タブ名は `STAFF_NOTES_TAB`（`off` で使わない）

**声の AI の読み方（2026-10-28 一畳屋様のご指摘：「承る」→「しょる」、「畳床」→「たたみゆか」（正しくは たたみどこ）、「見積り」→「けんつもり」）**：声の AI（GPT-Live・Realtime）は漢字の読みを取り違えることがあるため、声の AI に渡す文（声の AI と委任先の指示・`search_knowledge` の答え）では、読み間違えやすい言葉をひらがなにします（`src/lib/voice-words.ts` の `speakableWords`）。

## 3.5 OpenAI の使い方（回答の精度とトークン）

**資料の全文を読んで答える（NotebookLM と同じ方式）**：あいさつ・お礼以外のご質問（料金・工期・営業時間・営業範囲・店舗など）は、すべて AI が**指定のスプレッドシートの全文**（約 1.7 万字・約 1.6 万トークン）を読んで答えます。回答の根拠はスプレッドシートだけで、ホームページは使いません（2026-10-23〜。一畳屋様のご要望）。
- 以前は料金の質問を料金表から直接（AI を使わずに）答えていましたが、聞き方によって品目・作業を取り違えた（「襖の張替えは1枚いくら？」に行の名前に「１枚」とある「枠交換（１枚）」の金額）ため、料金も AI が料金表の該当する行・列を確かめて答えます。AI に渡す資料には、料金表ごとの金額の単位（1畳あたり・1枚あたり）と「料金表の見方」を添えています。
- 数量のある質問（「畳の表が6枚」「8畳を古都で」「網戸2枚と障子3枚」など、聞き方が違っても）は、システムが料金表の単価×数量を種類ごとに計算した「数量の計算表」（`src/lib/quantity.ts`）を添え、AI はその金額で種類ごとの合計・範囲を答えます（AI の計算の誤りを防ぐ）。4畳半など半畳を含む数量は、半畳の8掛けなど注記を反映した見積の計算（`src/lib/quote.ts`）を添えます。
- **答え方は優秀な受付担当者のように**（2026-10-24〜・回答の書き方の版 8。一畳屋様のご要望「知っている情報をすべて伝えるのではなく、お客様の疑問や不安を解消し、自然に見積依頼へつなげる」）：答えの量と範囲を、質問の具体性とお客様の意図に合わせます（テキスト・音声で共通）。
  - 漠然とした質問（「網戸4枚でいくら？」）：まず一般的な条件の目安を 1 つ（諸経費込み。数量の計算表の「標準の目安」をシステムが計算：網戸は基本の網の「大」、襖はいちばん安い紙の片面、障子は「エコノミー」の大、畳は一番人気の種類＋よく選ばれるヘリ）と、条件で変わることを一言、答えを絞る簡単な質問を 1 つ。例「一般的な大きさの網戸で、標準的な網なら4枚で16,500円（税込・諸経費込み）が目安です。…ベランダに出るような大きなタイプでしょうか？」。種類別・サイズ別の一覧や聞かれていないこと（新調・工期など）は最初は出しません。
  - 具体的な質問（商品・仕様の指定、違い・選び方・一覧）：必要なだけ詳しく（主な種類を安い順に・一番人気・耐用年数・別途の費用・工期など）。
  - お客様が条件を答えたら絞り込んで会話を深め、お見積りは決まり文句にせず、流れに応じて自然に提案します（「正確な金額は無料の訪問見積もりでご案内できます。よろしければ、ご都合のよい日にお伺いしましょうか？」）。
  - 数量があれば合計はシステムの計算のとおり。張替えと別の作業の行（枠交換・ウラ返しなど）は、聞かれたときだけ計算に入れます。資料にないこと（駐車場・保証・家具の移動など）は推測せず「お答えできかねます」と案内します。
- **学習済みの回答（同じ質問は AI を使わない）**：AI が一度作った回答を覚えておき、同じ質問には AI を使わずにそのまま返します（トークンがかからず、すぐに表示）。照合するのは、AI に渡す指示の全文（ルール・スプレッドシートの全文・数量の計算表）・モデル・考える深さ・お客様の質問（AI に渡す直近の質問すべて。「ですか」「？」などの言い回しの違いはそろえる）がまったく同じときだけです（`src/lib/learned.ts`）。意味が近いだけの質問（「6枚」と「8枚」など）には使いません。スプレッドシートを書き換える・回答の書き方を変える・モデルを変えると、自動的に新しく答え直します。答え直しのモデルの回答・途中で切れた回答・お名前や電話番号を含む会話は覚えません。Redis に 1 回答 1 キーで 30 日（`ANSWER_CACHE_DAYS`）保存し、管理画面「AIの学習状況・情報源」の「学習済みの回答」で確認・削除できます（削除すると次は AI が答え直す）。`ANSWER_CACHE=0` で使いません。
- **モデル（2026-10-23〜）**：文字の相談は `gpt-6-astra`（OpenAI の最上位）を考える深さ low で、声の相談は `gpt-6.1-sol`（low。待ち時間を短く）で答えます。混み合っている・一時的な障害（429・5xx）や、その API キーでは使えないモデル（403・404）のときは `gpt-5.6-sol` で答え直し、理由を管理画面の「エラー履歴」に記録します。見積の聞き取り・要約などは `OPENAI_CHAT_MODEL`（`gpt-4.1-mini`）のまま。
- **モデルの比較（2026-10-23）**：NotebookLM と同じ水準の答え方を求める 32 問（数量の計算・複数の品目・商品の違い・工期・支払い・資料にないこと）で、別のモデル（gpt-6.1-sol・考える深さ high）が資料と照らして採点（正確さ・答えの十分さ・資料にない記述・計算の誤り）。gpt-6-astra（low・根拠の引用なし）が正確さ 4.97／5・十分さ 4.91／5・計算の誤り 0 で最もよく、平均 5.8 秒。gpt-6.1-sol（low・medium）・gpt-6-astra（medium）・gpt-5.6-sol も正確さはほぼ同じで、十分さが少し低い（4.69〜4.88）。声の回答 15 問では gpt-6.1-sol（low）が正確さ 5.00・十分さ 4.93・平均 4.7 秒で最もよかった。
- 考える深さのあるモデルは考える中で根拠を確かめるので、答える前の根拠の引用（【根拠】）は既定では書かせません（比較でも、書かせないほうが十分で速かった。`ANSWER_EVIDENCE=1` で書かせる）。
- 費用（2026-10-23 に実際のトークン数で計算。資料の部分はプロンプトキャッシュが効く）：文字の相談 1 問あたり約 3〜10 円（gpt-6-astra。料金の一覧のような長い答えほど高い）、声の相談 1 問あたり約 0.5 円（gpt-6.1-sol。キャッシュの切れた最初の 1 問は約 5 円）。
- 声の相談の `search_knowledge` も同じ方式の回答（answer）を返すので、文字と声で答えが揃います。
- `ANSWER_CONTEXT=search` にすると以前の方式（関係する部分だけ・料金は料金表から直接）に戻せます。資料が 15 万字を超えた場合も自動で以前の方式になります。

**声と話し方**：AI の声は `sage`（20代の女性の明るく澄んだ声。marin・sage・coral・shimmer を同じ文 × 6 回で比べ、声の高さ・聞き取りやすさ・文の途中の途切れの少なさで最もよかった声）を標準の速さで（50代以上のお客様が聞き取りやすく、金額も聞き違えにくい。以前は 1.1 倍）。日本語を母語とする人の自然な発音・読み方（「一畳屋＝いちじょうや」「表替え＝おもてがえ」「6畳＝ろくじょう」など）を指示しています（指示がないと「一畳屋」を読み間違えることがありました）。AI が話しているかは、受信した AI の音声の音で判定します（`gpt-realtime-2.1` は「再生が終わった」の知らせを届けないことがあるため）。

**声の相談は GPT-Live（2026-10-27〜）**：一畳屋様のご要望「ChatGPT の音声会話（GPT-Live-1.1）か、その一つ前の世代に近い自然さ」に合わせ、声の相談を `gpt-live-1`（ChatGPT の音声会話と同じ仕組みの、聞きながら話せるモデル。GPT-Live-1.1 はまだ API で使えないため、その一つ前の世代）に切り替えました（`OPENAI_VOICE_ENGINE=live`）。
- 声の AI（GPT-Live）は話し方・相づち・割り込み・話し終わりの判断・聞き取りを受け持ち、事実と見積依頼の確認画面は委任先のモデル（`gpt-6.1-terra`）が `search_knowledge`（文字の相談と同じ、スプレッドシートの全文から答える AI）と `propose_estimate_request` を呼んで行います（`src/app/api/live/session`・`useVoiceSession.ts` の GPT-Live の部分・`prompts.ts` の `buildLiveInstructions`）。声は日本語の `harema`。
- 試験（50〜70代の方の話し方の読み上げ音声で、一畳屋様の例の会話を声で通す `live-scenario`）：網戸 4 枚の目安（1万6500円）→ ベランダの大きな網戸 → 訪問見積の提案 →「お願いします」→ お名前 → ご住所 → 番地の訂正 → ご希望日 → お電話番号 → 確認画面、まで自然に進み、確認画面にはお名前・ご住所（訂正後）・お電話番号・ご希望日・ご相談内容が正しく入りました。外壁塗装の相談＋お名前の訂正（山田→山下）＋お電話番号の訂正（3333→3334）＋「来週の水曜」の会話でも、確認画面の内容と要約（「築20年の2階建て住宅で、ひびが入ってきた外壁の塗装…」）が正しく入りました。返事までの間は約 1〜2 秒。聞き取りに自信がないときは、推測せずに聞き返します。

以下は、AI を使うかどうかの判定です。

| 順 | 判定 | 回答のしかた | OpenAI |
| --- | --- | --- | --- |
| 1 | あいさつ・お礼 | 定型文 | 使わない |
| 2 | 前と同じ質問（AI に渡す内容とお客様の質問がまったく同じ） | 学習済みの回答をそのまま返す | 使わない |

## 4. 見積受付の流れ（3 窓口共通）

1. 相談対応（ナレッジに基づく回答）
2. 見積希望 → **AI が会話の中で 1 つずつ**、お名前 → 訪問先のご住所 → 訪問のご希望日（第1〜第3希望）→ ご連絡先のお電話番号 の順に伺い、ご相談内容を AI が要約
   - 文字の相談：AI の「よろしければ、ご都合のよい日にお伺いしましょうか？」に「お願いします」と答えたとき（`acceptsOffer`）、または「見積をお願いします」（料金の回答の下の「このままチャットで見積を依頼する」）で始まります。答えを短く受け止めてから次を伺います（「山田様ですね。続いて、訪問先のご住所をお願いします」）。まとめて答えていただいた項目は聞き直しません。伺う文は決まった文で、日程を約束しません（`src/lib/intake.ts`・`intake-ai.ts`）。途中のご質問には答えてから続きを伺い、「やっぱりやめます」で中止、そろったあとの「電話番号は〜に変更」も反映します
   - そろったら「網戸4枚の張替えのお見積りですね。お名前・ご住所・お電話番号・訪問のご希望日をまとめましたので、内容をご確認ください」と伝え、**伺った内容が入った確認画面が自動で開きます**（お客様は確認して送信するだけ）
   - 会話が成立するように（2026-10-29 のご指摘「質問に対して的外れな返答」EST-20261029-KIJJ。お名前を伺ったときの「一番安いのでお願いしまう」をお名前に、続く「亀井です」をご住所にしていた）：
     - お名前らしくない答え（「お願い」「安い」「ので」・品物・料金の言葉を含む）はお名前にしません。ご住所らしくない答え（市区町村・町・丁目・番地・数字がない「亀井」）はご住所にしません（規則でも、AI の読み取りでも。`intake.ts` の `plausibleName`・`notAName`・`plausibleAddress`）
     - 伺った項目の答えがなく、ご依頼の内容（「畳は6枚、襖は押入れが2枚です」「一番安いのでお願いします」）を話されたときは、その内容に先に答えてから伺い直します（決まった文だけを返さない）。この答えでは、お見積りの提案や質問を重ねません
     - 最初の「見積をお願いします」に品物が入っていて、まだ料金をご案内していないときは、同じ返事の中で先に目安をご案内してからお名前を伺います（「団地を退去するので、畳と襖の見積もりを」→ 資料の退去の料金：畳 1 枚 8,250円・押入れの襖 7,150円 など）。聞き取りの途中の答えにも、それまでのご相談（退去など）を渡します（以前は「見積をお願い」を含む発言を除いていたため、ふつうの料金で答えていました）
   - 声の相談：AI が同じ順に 1 つずつ伺い、そろったら復唱せずに確認画面を表示します（Realtime の `propose_estimate_request`／簡易音声モードはエージェント）
   - 会話より前に出た内容（文字の相談で伺ったお名前など）は聞き直しません。伺った内容は会話と一緒にこの端末に保存され、文字 ⇄ 声を切り替えても引き継がれます
3. **伺った内容とご相談内容の要約が入った確認画面**（聞き取りがそろうと自動で開く。「見積依頼」ボタンでも開く）（文字・声で共通の `EstimateForm`）
   - 開くときに会話全体から読み取り直し（`/api/estimates/draft`。OpenAI があれば訂正や「来週の火曜」も反映、なければ規則で）、伺えなかった項目だけ入力欄で表示。入っている項目も「修正」から直せます。お客様は内容を確認して送信するだけ（`confirmed=true` でないと API が受け付けません）
   - 電話／LINE：AI が全項目を復唱し「この内容でお間違いないでしょうか」→「はい」で確定
4. スプレッドシート（受付一覧）へ記録：**対応状況**・受付日時・受付経路・氏名・住所・電話番号・相談内容（AI要約）・第1〜第3希望・受付番号の 11 項目（2026-10-28 一畳屋様のご依頼で整理）
   - 対応状況は一番左の列で、「未連絡」「連絡済」の 2 択のプルダウン。受付時は「未連絡」。各店舗・営業担当に LINE で引き継いだら「連絡済」に（シートでも管理画面でも変えられ、どちらにも反映）
   - 値は見出しで列を探して入れます（担当者が「担当者」「メモ」などの列を足しても、並べ替えても正しい欄に入ります）。AI が会話から入れた項目・お客様が修正した項目は、管理画面の受付の詳細にだけ表示します（シートには記録しません）
   - 整理前の 13 項目のタブは、2026-10-28 に既存の「受付一覧」タブをそのまま並べ替えて移行済みです（「確認状況」「会話からの自動入力」の列を削除・「ステータス」の列を一番左に移して「対応状況」に改名・「新規」→「未連絡」・「相談内容（AI要約・お客様確認済み）」→「相談内容（AI要約）」・A 列にプルダウン。行・書式はそのまま。10 件を移行前と照合済み）。整理前の見出しのタブでも読み書きできます
5. 事務担当者が、受付を担当店舗・営業担当に **LINE で共有**（2026-10-28 一畳屋様のご依頼。ここで受付業務は完了）。送る文は氏名・住所・電話番号・相談内容・訪問希望日（と受付番号）で、スプレッドシートと管理画面で同じ文です
   - **スプレッドシート**（`gas/LineShare.gs`）：「受付一覧」で行を選び（複数行・10 件まで）、メニュー「LINE共有」→「選択した受付をLINE用にコピー」→「コピー」→ LINE のトークに貼り付けて送信 →「連絡済にする」で対応状況が「連絡済」に。パソコンのブラウザで使えます（Google スプレッドシートのスマホアプリでは、スクリプトのメニュー・ボタンは動きません）
     - 設定（最初に 1 回）：スプレッドシートの「拡張機能」→「Apps Script」→ ファイルの「＋」→「スクリプト」で `LineShare` を作り、`gas/LineShare.gs` を全部貼り付けて保存 → スプレッドシートを再読み込み → 初回だけ Google の権限の確認で「許可」。シートに「LINE共有」ボタンを置くときは、図形描画のボタンに「スクリプトを割り当て」で `lineShareSelected`
     - 権限は `@OnlyCurrentDoc`（このスプレッドシートだけ）。行は受付番号で探すので、画面を開いたあとに並べ替えても正しい行が「連絡済」になります。フィルタ・非表示で隠れた行は共有しません
   - **管理画面**（受付一覧の各受付の「LINE共有」）：スマホは LINE が開き、文が入った状態で送り先を選ぶだけ（LINE の `line.me/R/share` のリンク。パソコン版の LINE では使えないため）。パソコンは文をコピーして LINE に貼り付け。対応状況はとなりのプルダウンで「連絡済」に
   - 送り先を選ばずに自動で送る仕組み（LINE 公式アカウントの Messaging API）は、各店舗のグループへの招待・送り先の対応表・月の通数の上限（無料は 200 通）が要るため、今は入れていません（LINE Notify は 2025-03-31 に終了）
6. 担当者（各店舗・営業担当）が折り返してお見積り訪問の日程を確定（AI は日程を確定しません）。お見積りは担当者が現地を見てから提出します
7. （任意）お客様の LINE との連携：受付完了画面に「LINEでもご連絡を受け取れます」を表示。お客様が公式LINEを友だち追加して受付番号を送ると、その受付に LINE が紐づき、管理画面に「LINE連携済み」と表示されます（日程確定後のやり取りを LINE でも行えるように）

> ご相談の入口は AI 相談に一元化しています（ヘッダーの「LINEで相談」の位置は「AIに相談」に変更）。LINE は受付後の出口・第 2 段階の連絡手段としてのみ案内します。

## 5. AI電話受付（Twilio）

```
お客様 → NTT 0120番号（転送設定）→ Twilio 番号 → POST /api/twilio/voice
   ├ 営業時間内 かつ「営業時間外のみAI」設定 → <Dial> スタッフ転送
   └ それ以外 → <Gather input="speech"> ⇄ POST /api/twilio/gather（AI 応答ループ）→ 受付完了で <Hangup>
```

1. Twilio で日本の番号を取得し、0120 番号の転送先に設定（0120 番号は継続利用）
2. Twilio 番号の Voice Webhook に `https://<公開URL>/api/twilio/voice`、Status Callback に `/api/twilio/status`
3. `.env` に Twilio 各種・`STAFF_FORWARD_NUMBER`・`PUBLIC_BASE_URL` を設定
4. 管理画面「電話・営業時間」で **常時AI／営業時間外のみAI／常にスタッフ** を切替、営業時間・休業日・転送先を設定（既定：営業時間外のみAI・月〜金 8:00〜17:00。土日・時間外は AI が受付。年末年始・GW・お盆休みは休業日に日付を登録。祝日は営業日が多いため、休む祝日だけ登録）

AI 電話受付では、折り返し先の電話番号を伺う際に「いまおかけの番号でよろしいでしょうか」と確認し、お客様が同意すれば発信者番号を使います（非通知の場合は番号を伺います）。

お客様向けの画面では、電話はふつうの電話ボタン（`tel:` リンク）に「営業時間外・土日はAIが受付」と添えて案内するだけです（文言は `src/lib/brand.ts` の `phoneAiNote`）。

ブラウザの `/phone` ページは、同じ応答エンジン（`src/lib/agent.ts`）を使う**スタッフ用のテスト画面**（通話シミュレーター）です。お客様向けのメニューには表示せず、検索エンジンにも載せません（`noindex`）。管理画面「電話・営業時間」の「電話受付のテストを開く」から開けます。Twilio 未設定でも電話フロー全体（相談 → 聞き取り → 復唱確認 → 登録）を試せます。

> さらに自然な電話会話（Realtime API × Twilio Media Streams）は WebSocket サーバーが必要なため、本デモでは Gather 方式を採用しています。応答ロジックは共通のため、将来の差し替えが可能です。

## 6. LINE Messaging API

1. LINE Developers で Messaging API チャネルを作成
2. Webhook URL に `https://<公開URL>/api/line/webhook` を設定し、Webhook を有効化
3. `.env` に `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` / `NEXT_PUBLIC_LINE_ADD_FRIEND_URL`

友だち追加時に挨拶、テキストで相談対応、「見積を依頼したい」で受付フロー（復唱確認付き）へ。クイックリプライで確認・修正を選べます。

受付番号（`EST-YYYYMMDD-XXXX`）が送られてきた場合は、その受付と LINE を紐づけて返信します（全角・小文字でも認識。別の LINE アカウントに紐づいた受付は上書きしません）。紐づけは管理画面の受付一覧に「LINE連携済み」として表示され、以降のご連絡は LINE 公式アカウントのチャットでも行えます。

## 7. 管理画面（`/admin`）

ChatGPT のようなシンプルな画面です（左にメニュー、上にヘッダー、中央に内容）。お客様向けサイトのヘッダーは表示しません。`/admin?view=receptions` のように各画面を直接開けます。管理画面から情報を追加・アップロードする機能はありません（AI の情報源は指定の Googleスプレッドシートだけ）。

- **AIの学習状況・情報源**（最初に開く画面）：回答に使う Googleスプレッドシートの URL の設定と接続状況（接続中／読み取れない理由）、スプレッドシートの再読み込み、回答テスト、AI の利用状況（AI なしで答えた割合・トークン数）、学習済みの回答、答えられなかった質問
- **登録済みナレッジ**：AI が使う情報の一覧（情報源・分類・キーワードで絞り込み）。読み取り専用（内容はスプレッドシートで直す。ホームページは再学習）
- **AIに質問（テスト）**：お客様と同じ AI に質問して、登録した情報で答えるか確認（どの情報を根拠にしたか・AI を使ったかを表示。会話は「テスト」として会話履歴に保存）
- **受付一覧**：3 窓口＋LINE の受付を検索・絞り込み・対応状況（未連絡／連絡済）の変更・**LINE共有**（担当店舗・営業担当への引き継ぎ。§4 の 5）・CSV 出力（シートと同じ 11 項目。受付後に LINE とつながった受付は「LINE連携済み」）。スプレッドシートに記録しているときは、一覧はシートの「受付一覧」タブから読み、対応状況を変えるとシートの「対応状況」の欄も書き換えます（列は見出しで探すので、担当者が「担当者」「メモ」などの列を足しても動きます）
- **会話履歴**：全窓口の会話ログを閲覧
- **エラー履歴**：AI の回答・声の相談の接続・LINE・スプレッドシート（読み取り・受付の記録）のエラーを 1 か所で確認
- **電話・営業時間**：AI／人間の切替、営業日・時間、休業日、転送先、会社名、第一声、電話受付のテスト画面（`/phone`）へのリンク
- **接続状況**：スプレッドシート・OpenAI・受付の記録先・保存先・Twilio・LINE の設定状況、Webhook URL のコピー

### 9.1 お客様が迷わない・離脱しないための画面づくり

| 工夫 | 内容 |

| 入口は 1 つ | トップページの「AIに相談する」にそのまま相談の画面を置き、文字でもマイクのボタンで声でも相談できます（窓口を選ばせない）。途中で切り替えても会話はすべて引き継ぎ、声で話した内容も文字で残ります。メニューの「AI相談」・よくあるご質問の「AIにくわしく聞く」も、ページを移動せずにその画面で始めます |

## 10. 運用上の注意

- 会社情報・料金は一畳屋の顧客対応マニュアル（2026年8月1日改定の料金表）とご提供いただいた内容です。価格改定などは Excel を更新して `npm run knowledge:build` → 再デプロイ（スプレッドシート接続時はシート側）で反映してください。
- `data/runtime/` は実行時データ（受付・会話・設定）で Git 管理外です。本番ではスプレッドシートが正となります。
- Vercel 等のサーバーレス環境では §1.5 のとおりサービスアカウント（スプレッドシートの編集者）を設定してください。会話履歴・設定も残す場合は Upstash Redis も追加します。
- `/api/status` は、管理者としてログインしていないときは動作の有無だけを返します（シートの ID・サービスアカウント・Webhook・エラーの内容は管理画面でだけ表示）。
- 公開 API（チャット・音声・要約など）には IP ごとの簡易レートリミットを設けています（1 分あたり：チャット 20 回、音声セッション 10 回など）。OpenAI への各リクエストには 15〜55 秒のタイムアウトを設定し、関数の最大実行時間は 60 秒です。
- 写真は WebP（1x/2x）と PNG／JPEG フォールバックで配信します（実際に読み込まれるのは主に WebP。会社情報セクションの写真は遅延読み込み）。
